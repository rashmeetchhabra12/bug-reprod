ReproWitness

A local browser-evidence tool for requirement-guided exploration and reported-bug reproduction. An external agent chose the live actions through local tools; deterministic replays used the exact same recipes. This page contains recorded reports, not a live service.

What this is

ReproWitness validates actions submitted by an external agent through a local service. Every action is schema-validated, recorded with an observation and screenshot, and checked against an expectation that was frozen before the action sequence.

The included runs use a synthetic task-list fixture. On the buggy build, adding a task appears to work but the task is gone after reload; adding a second task also replaces the first. On the fixed build the same recipes pass unchanged.

Run the actual tool locally

Windows 11, PowerShell 5.1, from the repository root:

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m playwright install chromium

.\scripts\demo.ps1 start
# see docs\USAGE.md and docs\EXAMPLES.md for a full investigation
.\scripts\demo.ps1 stop

The script starts the buggy task app on 127.0.0.1:8103, the fixed app on 127.0.0.1:8104, and the agent service. It refuses to start if either port is occupied and never kills an unrelated process. The service is loopback-only; its token is stored outside the repository and is not printed.

Full workflow: docs\USAGE.md, docs\EXAMPLES.md and docs\ALAN_INTEGRATION.md.

Scope

  • Live decisions are labelled alan-agent. Recorded replays are labelled recorded-replay and make no model calls.
  • The reports are static recorded evidence. They do not launch the agent or contact the service.
  • Reports record observed behavior, not a root cause.
  • Local loopback targets, Chromium, supported actions and checks, and no automatic code repair.
  • No credentials, personal paths or service state are included in this showcase.
